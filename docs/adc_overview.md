### 29.4.3 ADC 时钟

ADC 采用双时钟域架构：**ADC 时钟独立于 AHB 总线时钟**。

#### 两种时钟方案

**方案 1：独立时钟（`adc_ker_ck`）**
- CKMODE[1:0] = `00`（ADCx_CCR 寄存器）
- 独立于 AHB 时钟的专用时钟源
- 可以在 RCC 中配置 `adc_ker_ck` 时钟频率
- 优点：可以达到最高 ADC 时钟频率，不受 AHB 总线时钟限制
- ADC 时钟可进一步分频：`/1, /2, /4, /6, /8, /10, /12, /16, /32, /64, /128, /256`
  （通过 ADCx_CCR 的 PRESC[3:0] 配置）

**方案 2：AHB 时钟分频**
- CKMODE[1:0] ≠ `00`
- 从 AHB 时钟分频而来：`/1, /2, /4`
- 优点：无时钟域同步问题，定时器触发的 ADC 转换无额外抖动

#### 时钟约束

| 条件 | 时钟比要求 |
|------|-----------|
| 所有通道为 16/14/12/10 位 | Fadc_hclk ≥ Fadc_ker_ck / 4 |
| 存在 8 位通道 | Fadc_hclk ≥ Fadc_ker_ck / 3 |

多个 ADC 同时使用时必须使用**同一个时钟源**（不带预分频器）从 RCC 输入。

#### BOOST 控制

通过 ADC_CR 寄存器的 BOOST 位设置，必须根据 ADC 时钟频率正确配置。

### 29.4.5 AHB 从机接口

ADC 实现了一个 AHB 从机端口，用于控制/状态寄存器和数据访问。

- 字（32 位）访问
- 单周期响应
- 所有读写访问均为零等待
- 不支持 split/retry 请求，从不产生 AHB 错误

### 29.4.6 ADC 深度掉电模式（DEEPPWD）与电压调节器（ADVREGEN）

默认情况下，ADC 处于深度掉电模式，内部电源被切断以降低漏电流（复位后 ADC_CR 的 DEEPPWD=1）。

**启动顺序：**
1. 清除 DEEPPWD=0，退出深度掉电
2. 设置 ADVREGEN=1，使能内部 LDO 稳压器
3. 软件必须等待稳压器启动时间 TADCVREG_STUP（查数据手册）
4. 可检查 ADC_ISR 的 LDORDY 位确认 LDO 就绪

**关闭顺序：**
1. ADEN=0 禁用 ADC
2. ADVREGEN=0 关闭 LDO（可选省电）
3. DEEPPWD=1 重新进入深度掉电（进一步省电）

**注意事项：**
- DEEPPWD=1 会自动清除 ADVREGEN
- 写 DEEPPWD=1 时，写入顺序应该先设 DEEPPWD=1（它会自动清 ADVREGEN）
- 仅关闭 LDO（ADVREGEN=0 但 DEEPPWD=0）：**内部模拟校准值保留**
- 进入深度掉电（DEEPPWD=1）：**内部模拟校准值丢失**，需要重新校准或重新写入之前保存的系数

---

### 29.4.7 单端与差分输入通道

通过 **ADC_DIFSEL** 寄存器的 DIFSEL[19:0] 位逐通道配置，**必须在 ADC 禁用时写入**（ADEN=0）。

**单端模式：**
- 转换电压 = VINP[i]（正输入） - VREF-（负参考）
- 使用 INP 引脚即可

**差分模式：**
- 转换电压 = VINP[i]（正输入） - VINN[i]（负输入）
- 需要同时使用 INP 和 INN 引脚
- 输出数据为**无符号数**：
  - VINP[i] = VREF-，VINN[i] = VREF+ 时 → 0x0000（16位分辨率）
  - VINP[i] = VREF+，VINN[i] = VREF- 时 → 0xFFFF
- 转换值计算公式：
  Converted Value = ADC_Full_Scale × (VINP - VINN) / (VREF+ - VREF-) × (-1) + ADC_Full_Scale / 2
- 差分模式下两个输入端应偏置在 VREF+/2
- 输入信号应为差分信号（共模电压应固定）

**注意事项：**
- 通道 "i" 配置为差分时，其负输入 VINN[i] 被占用。连接到同一 VINN[i] 的通道 "i+n" 不能同时被不同的 ADC 转换
- 部分通道在 ADC1/ADC2 之间共享，差分配置可能使另一 ADC 的对应通道不可用

### 29.4.8 校准（ADCAL, ADCALDIF, ADCALLIN, ADC_CALFACT）

每个 ADC 提供自动校准流程，包含上电/下电序列。校准期间，ADC 计算校准系数（11 位偏移或 160 位线性），内部应用于 ADC 直到下次断电。

校准是任何 ADC 转换的前提，用于消除芯片间的系统误差，补偿偏移和线性偏差。

#### 偏移校准与线性校准

| 配置 | 说明 |
|------|------|
| ADCALDIF = 0 | 校准用于**单端输入**转换 |
| ADCALDIF = 1 | 校准用于**差分输入**转换 |
| ADCALLIN = 1 | 同时执行线性校准和偏移校准 |
| ADCALLIN = 0 | 仅执行偏移校准，不执行线性校准 |

线性校准**只需做一次**（不受单端/差分影响）。

#### 基本校准流程（6 步）

1. 确保 DEEPPWD=0、ADVREGEN=1，等待 LDO 稳定（检查 LDORDY）
2. 确保 ADEN=0（ADC 禁用）
3. 配置 ADCALDIF（单端/差分）和 ADCALLIN（是否线性校准）
4. 设置 ADCAL=1（启动校准）
5. 等待 ADCAL=0（硬件自动清零表示完成）
6. 读取校准系数：
   - 偏移系数 → ADC_CALFACT 寄存器的 CALFACT_S[10:0] 或 CALFACT_D[10:0]
   - 线性系数 → ADC_CALFACT2 寄存器（需遵循线性系数读取流程，且 ADEN=1）

#### 线性校准系数的读取流程（20 步）

校准完成后（ADCAL=0），ADC_CR 中的 6 个 LINCALRDYW1..6 位被置 1。读取需要 6 轮，每轮操作一个 LINCALRDYWx 位：

| 轮次 | 位 | 线性系数位域 | 有效位数 | 说明 |
|------|---|-------------|---------|------|
| 1 | LINCALRDYW6 | [159:150] | 10 位 | 注意：写 ADC_CALFACT2[9:0] |
| 2 | LINCALRDYW5 | [149:120] | 30 位 | |
| 3 | LINCALRDYW4 | [119:90] | 30 位 | |
| 4 | LINCALRDYW3 | [89:60] | 30 位 | |
| 5 | LINCALRDYW2 | [59:30] | 30 位 | |
| 6 | LINCALRDYW1 | [29:0] | 30 位 | |

每轮操作步骤：
1. 清除对应的 LINCALRDYWx 位（写 0）
2. 轮询该位直到硬件返回 0（表示数据已就绪）
3. 读取 ADC_CALFACT2[29:0]

**前提条件：** ADEN=1 且 ADSTART=0、JADSTART=0（ADC 使能且无转换进行中）

**注意：** 一次只能操作一个 LINCALRDYWx 位，不能同时改多个位。

#### 线性校准系数的写入流程（20 步）

用于恢复之前保存的线性校准系数（掉电后重新注入）：

1. 确保 DEEPPWD=0、ADVREGEN=1，检查 LDORDY
2. 设 ADEN=1，等 ADRDY=1
3. 每轮：先写 ADC_CALFACT2[29:0] → 设对应 LINCALRDYWx 位（写 1） → 轮询直到硬件返回 1（表示写入完成）

**前提条件：** ADEN=1 且 ADSTART=0、JADSTART=0

#### 混合单端和差分输入的校准策略

如果 ADC 同时使用单端和差分通道，需要做两次校准：

1. 禁用 ADC
2. **第一次校准**：ADCALDIF=0（单端）+ **ADCALLIN=1**（含线性校准）
   - 更新 CALFACT_S[10:0] 和 LINCALFACT[159:0]
3. **第二次校准**：ADCALDIF=1（差分）+ ADCALLIN=0（仅偏移，无需再做线性）
   - 更新 CALFACT_D[10:0]
4. 使能 ADC，配置通道，启动转换

之后，每次从单端通道切换到差分通道（或反之），ADC 硬件会自动注入对应的校准因子，无需软件干预。

#### 校准系数保持与恢复

| 状态 | 校准系数状态 |
|------|-------------|
| ADEN=0（仅禁用） | 内部校准值保留 |
| ADVREGEN=0（关 LDO） | 内部校准值保留 |
| DEEPPWD=1（深度掉电） | 内部校准值丢失 |
| STANDBY/VBAT 模式 | 内部校准值丢失 |

**恢复方法：**
- 方法一：重新执行校准流程
- 方法二：写入之前保存的校准系数（省时间）
  - 偏移系数写入 ADC_CALFACT（CALFACT_S / CALFACT_D）
  - 线性系数通过 LINCALRDYW1..6 流程写入 ADC_CALFACT2
  - ADC 使能且未转换状态写入（ADEN=1, ADSTART=0, JADSTART=0）
  - 下次启动转换时自动注入，**零延迟**

**VREF+ 变化超过 10%** 时建议重新校准。

### 29.4.9 ADC 使能与禁用（ADEN, ADDIS, ADRDY）

先完成上电准备（DEEPPWD=0, ADVREGEN=1，等待 LDORDY），然后：

#### 使能 ADC 流程

1. 写 1 清除 ADC_ISR 的 ADRDY 位
2. 设 ADEN=1
3. 等待 ADRDY=1（ADC 经过 tSTAB 稳定时间后自动置位，也可使能 ADRDYIE 中断）
4. 可选手动清 ADRDY

使能后，设 ADSTART=1 启动常规转换，或 JADSTART=1 启动注入转换（也可等待外部触发）。

#### 禁用 ADC 流程

1. 确认 ADSTART=0 且 JADSTART=0（无转换进行中）。如有需要，先设 ADSTP=1 / JADSTP=1 停止转换，等待 ADSTP=0 / JADSTP=0
2. 设 ADDIS=1
3. 可选等待 ADEN=0（硬件自动清除 ADEN 和 ADDIS）

#### 状态转换图

| ADC 状态 | 说明 |
|---------|------|
| OFF | 关闭状态 |
| Startup | 启动中（tSTAB） |
| RDY | 就绪，可开始转换 |
| Converting CH | 正在转换 |

### 29.4.10 寄存器写入约束

不同寄存器的允许写入时机不同，违反会导致 ADC 行为异常且**无硬件保护**，恢复方法只能禁用 ADC（清 ADEN 及所有 CR 位）。

| 寄存器/控制位 | 允许写入条件 |
|-------------|------------|
| DIFSEL（ADC_DIFSEL）、ADC_CCR、ADCAL、ADEN | ADEN=0（ADC 禁用） |
| ADSTART、JADSTART、ADDIS | ADEN=1 且 ADDIS=0（ADC 使能且无禁用请求） |
| CFGR、SMPRy、TRy、SQRy、OFRy、IER 中与**常规转换**相关的位 | ADSTART=0（无常规转换进行中） |
| 与**注入转换**相关的配置位 | JADSTART=0（无注入转换进行中） |
| JSQR | 随时可写（ADEN=1），除非上下文队列模式禁用（JQDIS=0）时需 JADSTART=0 |
| ADSTP / JADSTP | ADSTART=1 或 JADSTART=1，且 ADDIS=0 |

### 29.4.11 通道选择（SQRx, JSQRx）

每个 ADC 有最多 **20 个 VINP[x]** 通道选择位（20 选 1 MUX）：
- **6 个快速通道**：VINP[0:5]（来自 ADCx_INP/INN[0..5]）
- **14 个慢速通道**：VINP[6:19]（来自 ADCx_INP/INN[6..19]）
- **6 个内部通道**（仅在 ADC2 上，占用 VINP 位置，非额外通道）：

| 内部信号 | 占用 VINP | 使能控制位 |
|---------|----------|-----------|
| VSENSE（温度传感器） | ADC2 VINP[12] | TSEN（ADC_CCR） |
| VREFINT（内部参考电压） | ADC2 VINP[13] / VINP[15] | VREFEN（ADC_CCR） |
| VBAT/4（电池电压监测） | ADC2 VINP[14] | VBATEN（ADC_CCR） |
| DAC_OUT1 | ADC2 VINP[16] | - |
| VDDCORE（内核电压监测） | ADC2 VINP[17] | VDDCOREEN（ADC2_OR） |
| DAC_OUT2 | ADC2 VINP[7] | - |

#### 两组转换序列

| 属性 | 常规组（Regular） | 注入组（Injected） |
|------|-----------------|-------------------|
| 最大转换数 | 16 | 4 |
| 配置寄存器 | ADC_SQR1 ~ SQR4 | ADC_JSQR（1 个） |
| 序列长度位 | L[3:0]（ADC_SQR1） | L[1:0]（ADC_JSQR） |
| 优先级 | 低 | 高（可中断常规转换） |

序列中的通道可以任意顺序排列，同一通道可重复出现。

#### JSQR 写入约束
- 默认（JQDIS=0，上下文队列使能）：ADEN=1 时可随时写
- 上下文队列禁用（JQDIS=1）：需 JADSTART=0

#### 内部通道使能

要使用内部模拟通道，必须先使能对应的控制位：
```c
ADC_CCR |= VREFEN;  // 使能 VREFINT
ADC_CCR |= TSEN;     // 使能 VSENSE
ADC_CCR |= VBATEN;   // 使能 VBAT
ADC2_OR |= VDDCOREEN; // 使能 VDDCORE 监测
```

### 29.4.12 通道预选寄存器（ADC_PCSEL）

**作用：** IO 上的模拟开关速度跟不上内部 ADC MUX 的切换速度，需要提前打开模拟开关。

**规则：**
- 在 SQRx/JSQRx 中选择的每个通道，必须预先配置对应的 ADC_PCSEL 位
- 选择基于 **VINP[i]**（不是 ADCx_INPy 编号）
- 差分模式时，正输入（VINP[i]）和负输入（VINN[i]）都需要在 PCSEL 中选上

### 29.4.13 可编程采样时间（SMPR1, SMPR2）

每通道独立配置采样时间，通过 SMP[2:0] 位选择：

| SMP[2:0] | 采样时钟周期 |
|----------|------------|
| 000 | 1.5 |
| 001 | 2.5 |
| 010 | 8.5 |
| 011 | 16.5 |
| 100 | 32.5 |
| 101 | 64.5 |
| 110 | 387.5 |
| 111 | 810.5 |

#### 转换时间计算

```
TCONV = 采样时间 + 7.5 个 ADC 时钟周期
```

**示例：** Fadc_ker_ck = 24MHz，采样时间 1.5 周期，14 位模式
```
TCONV = (1.5 + 7.5) / 24MHz = 0.375µs
```

#### 寄存器分配
| 寄存器 | 覆盖通道 |
|-------|---------|
| ADC_SMPR1 | VINP[0:9] |
| ADC_SMPR2 | VINP[10:19] |

采样结束时硬件置位 **EOSMP** 标志（仅常规转换）。

#### 采样时间约束
- 快速通道（VINP[0:5]）和慢速通道（VINP[6:19]）有不同的最小采样时间要求（查数据手册）
- VDDA 电压低时 IO 模拟开关电阻增大，需要更长采样时间
- 可通过 SYSCFG_PMCR 的 EN_BOOSTER 位使能内部升压器来降低低 VDDA 下的电阻

### 29.4.14 单次转换模式（CONT=0）

单次模式每次触发只执行一次转换序列，执行完停止等待下次触发。

**触发方式：**
- 设 ADSTART=1（常规，软件触发）
- 设 JADSTART=1（注入，软件触发）
- 外部硬件触发事件

必须先设 ADSTART/JADSTART，再等待外部触发（如果使用硬件触发）。

**常规序列流程：**
- 每转完一个通道 → 数据存入 ADC_DR，置 EOC（结束标志），可产生中断
- 整个序列完成 → 置 EOS（序列结束标志），可产生中断
- ADC 停止，等待下次触发

**注入序列流程：**
- 每转完一个通道 → 数据存入 ADC_JDRy（y=1~4），置 JEOC，可产生中断
- 整个序列完成 → 置 JEOS，可产生中断

只转换一个通道则将序列长度设为 1。

### 29.4.15 连续转换模式（CONT=1）

仅适用于**常规通道**。触发一次后自动循环执行转换序列，EOS 置位后立即重新开始。

- 注入通道不支持连续模式（除非 JAUTO 自动注入模式）
- **不能同时使能 CONT=1 和 DISCEN=1**（间断模式和连续模式互斥）

### 29.4.16 启动转换（ADSTART / JADSTART）

ADSTART 和 JADSTART 既是**控制位**也是**状态位**，反映是否有转换在进行。

#### 行为

| 操作 | 说明 |
|------|------|
| ADSTART=1 | 启动常规转换。EXTEN=0（软件触发）时立即开始；EXTEN≠0 时等待硬件触发边沿 |
| JADSTART=1 | 启动注入转换。JEXTEN=0（软件触发）时立即开始；JEXTEN≠0 时等待硬件触发边沿 |
| JAUTO=1 | 使用 ADSTART 启动常规+自动注入序列（JADSTART 必须保持为 0） |

#### ADSTART 清零时机（不同模式行为不同）

| 模式 | ADSTART 何时清 0 |
|------|----------------|
| 单次 + 软件触发（CONT=0, EXTEN=0） | 序列结束时硬件清 0（EOS=1） |
| 间断 + 软件触发（CONT=0, DISCEN=1, EXTEN=0） | 每次转换结束时清 0（EOC=1） |
| 连续模式（CONT=1） | 不清零（序列自动重启，EOS 不清 ADSTART） |
| 单次 + 硬件触发（CONT=0, EXTEN≠0） | **不清零**（防止丢失下次硬件触发） |
| 执行 ADSTP | 停止完成后清 0 |

JADSTART 类似，在注入序列完成（JEOS）或 JADSTP 后清 0。

**注意：** 软件触发时（EXTEN=0），EOC 标志仍为高时不应设置 ADSTART。

### 29.4.17 转换时序

```
TCONV = TSMPL（采样时间）+ TSAR（逐次逼近时间）
```

手册示例（14 位模式，Fadc_ker_ck = 24MHz）：
```
TCONV = 1.5 + 7.5 = 9 个 ADC 时钟周期 = 375ns
```

**时序图关键点：**
- 采样阶段（TSMPL）：由 SMP[2:0] 设定采样周期数
- 转换阶段（TSAR）：取决于分辨率设置 RES[2:0]
- 采样结束 → 硬件置 EOSMP
- 转换结束 → 硬件置 EOC，数据锁存到 ADC_DR

### 29.4.18 停止转换（ADSTP / JADSTP）

常规和注入转换可以独立停止，互不影响。

| 操作 | 效果 |
|------|------|
| ADSTP=1 | 中止当前常规转换，丢弃部分转换结果（ADC_DR 不更新） |
| JADSTP=1 | 中止当前注入转换，丢弃部分结果，序列重置（下次从头开始） |

**停止完成后：**
- ADSTP、ADSTART 或 JADSTP、JADSTART 由硬件清 0
- 软件必须轮询 ADSTART/JADSTART 直到为 0，确认完全停止
- 停止后 ADC 可重新配置（改通道、触发等）

**自动注入模式（JAUTO=1）：**
- 设置 ADSTP 会同时中止常规和注入转换
- **JADSTP 禁止使用（must not be used）**，因自动注入模式下注入序列由硬件联动控制，单独停止注入会导致状态不可控

### 29.4.20 注入通道管理

#### 触发注入模式（JAUTO=0，默认）

1. 启动常规转换（外部触发或 ADSTART=1）
2. 注入触发到来（硬件触发或 JADSTART=1）→ **中断当前正在进行的常规转换**，启动注入序列（全部注入通道转换一次）
3. 注入序列完成后，**恢复常规转换**，从被中断的那一笔继续
4. 若注入进行中来了常规触发 → **不打断注入**，等注入结束后再处理常规触发

**约束：** 两次注入触发的间隔必须大于注入序列的执行时间，否则可能丢失触发。

#### 自动注入模式（JAUTO=1）

常规序列全部完成后自动接着执行注入序列。

**配置要求：**
- **ADSTART=1** 启动（JADSTART 必须保持为 0）
- 外部注入触发必须禁用
- 不能和间断模式（DISCEN=1）同时使用

**与连续模式组合：**
- JAUTO=1 + CONT=1 → 常规 + 注入持续循环
- JAUTO=1 + CONT=0 → 每触发一次执行一轮（常规 + 注入），然后停止

**与 DMA 组合：**
- DMA 必须配置为**循环模式**（circular mode）
- 若配置为 DMA **单次模式**（single-shot mode），DMA 传输完成时整个 JAUTO 序列会停止
- 这是由 DMA 传输完成事件触发的停止，与 ADC 的 CONT 位无关

**停止：**
- 设置 **ADSTP** 同时中止常规和注入转换
- **JADSTP 禁止使用**

### 29.4.21 间断模式（DISCEN / DISCNUM / JDISCEN）

间断模式将完整的转换序列分成若干子组，每次触发只转换一个子组。

#### 常规组（DISCEN）

| 配置项 | 说明 |
|-------|------|
| DISCEN | 使能间断模式 |
| DISCNUM[2:0] | 每个子组的转换数 n（n ≤ 8） |
| L[3:0]（SQR1） | 总序列长度 |

**行为：** 每次外部触发转换**接下来 n 个**通道，直到所有通道转换完毕（产生 EOS）。之后的下一次触发重新从第一个子组开始。

**示例：** 序列 = {1,2,3,6,7,8,9,10,11}，n=3

| 触发次数 | 转换的通道 | 事件 |
|---------|-----------|------|
| 第1次触发 | 1, 2, 3 | 每次转完产生 EOC |
| 第2次触发 | 6, 7, 8 | 每次转完产生 EOC |
| 第3次触发 | 9, 10, 11 | EOC + EOS（序列结束） |
| 第4次触发 | 1, 2, 3 | 重新从第1个子组开始 |

- 最后一个子组可以少于 n 个通道
- **不能与 CONT=1 同时使用**（同时使能时 CONT 被忽略）

#### 注入组（JDISCEN）

行为与常规组类似，但 n 固定为 1，每次触发只转换**一个**注入通道。

**不能与 JAUTO=1 同时使用。**

### 29.4.22 注入转换上下文队列

上下文队列允许提前预设最多 **2 组**注入配置（触发设置 + 通道序列），硬件在每次注入序列完成后自动切换配置，减少软件干预。

#### 使能与禁用

| JQDIS | 行为 |
|-------|------|
| 0（默认） | 队列使能，**只能用硬件触发** |
| 1 | 队列禁用，可用软件触发 |

#### 队列中的上下文内容

每个上下文包含 ADC_JSQR 寄存器的全部字段：
- 触发极性和源（JEXTEN[1:0] + JEXTSEL[4:0]）
- 注入序列配置（JL[1:0] + JSQ1~JSQ4[4:0]）

#### 队列操作

| 操作 | 行为 |
|------|------|
| 写 ADC_JSQR | 压入队列。队列空时立即生效；有 2 组时新写入**溢出**（JQOVF 置位，写入被忽略） |
| 读 ADC_JSQR | 返回当前活跃上下文；队列空时返回 0x0000 |
| 注入序列完成 | 消耗一个队列位置，自动切换到下一个上下文 |
| JADSTP=1 或 ADDIS=1 | 清空队列（flush） |

#### JQM 位 — 队列空时的行为

| JQM | 队列空时的行为 |
|-----|-------------|
| 0 | 保留最后一个活跃上下文，继续接受硬件触发（**保守模式**） |
| 1 | 不再接受硬件触发（触发被忽略），直到软件重新写 ADC_JSQR（**安全模式**） |

#### 队列溢出管理

- 队列满（2 组）时写入新上下文 → JQOVF 置位，新写入被忽略
- 建议等待上一组注入完成（收到 JEOS）后再写新上下文，避免溢出

#### JSQR 编程注意事项

- **必须一次写完**（JL + JSQ1~JSQ4 同时写入）
- **不要用读-改-写**（read-modify-write）方式
- 队列使能时，写新上下文应确保没有正在进行的注入触发

#### 队列清空（Flush）场景

| 动作 | JQM=0 | JQM=1 |
|------|-------|-------|
| JADSTP=1 | 保留最后活跃上下文 | 队列变空，触发被忽略 |
| ADDIS=1 | 保留最后活跃上下文 | 队列变空 |

#### 空队列启动流程（仅 JQM=0）

用于 ADC 刚初始化时还不确定第一个注入上下文的情况：

1. 写 ADC_JSQR（JEXTEN ≠ 0）
2. 设 JADSTART=1
3. 设 JADSTP=1
4. 等待 JADSTART=0
5. 设 JADSTART=1（开始正常操作）

### 29.4.27 数据管理

#### 数据对齐

转换结果通过 ADC_DR（常规）和 ADC_JDRy（注入）读取，32 位寄存器。

对齐方式由 **ADC_CFGR2** 的 **OVSS[3:0]**（过采样右移）和 **LSHIFT[3:0]**（左移）控制：

| 对齐方式 | 说明 | 典型 LSHIFT 值 |
|---------|------|---------------|
| 右对齐 | 数据放在低位，高位补 0 | LSHIFT=0 |
| 左对齐 | 数据放在高位，低位补 0 | LSHIFT = 16 - 分辨率 |

过采样模式下 OVSS 控制右移位数以恢复期望的数据宽度。

具体对齐格式见手册 Figure 208~211（1535~1536页）。

#### 偏移（Offset）

四个偏移寄存器 **ADC_OFR1~4** 可分别分配给不同通道（OFFSETy_CH）。

**作用：** `最终结果 = 原始转换值 - OFFSETy[25:0]`

使能偏移后数据变为**有符号数**（SEXT 符号扩展位）。

**不同分辨率下 OFFSET 的对齐要求：**

| 分辨率 | 数据在 16 位字段中的位置 | OFFSET 低位必须为 0 |
|-------|------------------------|-------------------|
| 16位 | [15:0] | 无 |
| 14位 | [15:2] + 低 2 位=00 | OFFSET[1:0]=00 |
| 12位 | [15:4] + 低 4 位=0000 | OFFSET[3:0]=0000 |
| 10位 | [15:6] + 低 6 位=000000 | OFFSET[5:0]=000000 |
| 8位 | [15:8] + 低 8 位=00000000 | OFFSET[7:0]=000000 |

#### 16 位/8 位有符号格式处理（RSHIFTx / SSATE）

偏移使能后结果变为有符号数，可能超过标准 16 位有符号范围（例如 16 位分辨率 + OFFSET=0x8000，结果最小可达 0xFFFF8000）。三种处理方式：

| SSATE | RSHIFTx | 格式 | 数据范围 | 说明 |
|-------|---------|------|---------|------|
| 0 | 0 | 符号扩展 17 位 | 0xFFFF8000 ~ 0x00007FFF | 完整精度，但需 32 位读取 |
| 0 | 1 | 右移 1 位 | 0xC000 ~ 0x3FFF | 适配标准 16 位有符号，损失 1 位精度 |
| 1 | 0 | 饱和 16 位 | 0x8000 ~ 0x7FFF | 溢出值钳位到边界 |

**注意：** SSATE 和 RSHIFTx 仅支持 16 位（RES=000）和 8 位（RES=100）分辨率，过采样模式下不支持。

#### 偏移计算示例

| 原始值 | 偏移值 | SSATE=0 RSHIFT=0 | SSATE=0 RSHIFT=1 | SSATE=1 RSHIFT=0 |
|-------|-------|------------------|-----------------|-----------------|
| 0xFFFF | 0x8000 | 0x00007FFF | 0x3FFF | 0x7FFF |
| 0x8000 | 0x8000 | 0x00000000 | 0x0000 | 0x0000 |
| 0x0000 | 0x8000 | 0xFFFF8000 | 0xC000 | 0x8000 |

#### 常见用法

大多数应用使用**右对齐 + 无偏移**即可，软件自行做偏移计算和对齐处理，既简单又灵活。

### 29.4.27 续 — Overrun（溢出）

ADC_DR 有 **8 级 FIFO**，如果数据未及时读取（CPU 或 DMA），FIFO 满时新转换完成就会溢出。

OVR 标志置位，可产生中断（OVRIE=1）。**写 1 清除 OVR。**

| OVRMOD | 行为 | FIFO 状态 |
|--------|------|----------|
| 0 | 保留 FIFO 中已有数据，新转换结果**丢弃** | 使能（8 级） |
| 1 | 新结果**覆盖**旧数据，ADC_DR 始终保存最新值 | 禁用 |

**注入通道无溢出问题**（四个专用寄存器 ADC_JDR1~4）。

溢出后 ADC **仍可继续转换**，不会卡死。但 DMA 模式下溢出会阻塞 DMA 请求，直到软件清 OVR。

---

### 29.4.27 续 — 三种数据读取场景

| 场景 | 配置 | 说明 |
|------|------|------|
| 软件轮询/中断 | OVRMOD=0，用 EOC/EOCIE | 每次转换完读 ADC_DR，将溢出视为错误 |
| 只转换不读数（如模拟看门狗） | OVRMOD=1，忽略 OVR | ADC_DR 始终保留最新值，不关心溢出 |
| DMA 搬运 | DMNGT=01 或 11 | 自动搬运数据，溢出会阻塞 DMA 请求 |

---

### 29.4.27 续 — DMA 模式（DMNGT）

| DMNGT | 模式 | 行为 |
|-------|------|------|
| 01 | DMA 单次 | 每通道产生 DMA 请求。DMA 传输完成后：ADC_DR 冻结、**当前转换中止**、扫描序列停止并重置、不再发请求 |
| 10 | DFSDM 模式 | 数据直接传给 DFSDM 数字滤波器 |
| 11 | DMA 循环 | 每次有数据就发 DMA 请求，适合连续数据流 |

**FIFO 配合 DMA：**
- **SREQ** — 有 1 个数据时产生单次请求
- **BREQ** — 有 4 个数据时产生突发请求
- DMA2 根据自身配置选择合适的请求线

---

### 29.4.28 使用 DFSDM 处理转换

DFSDM（Digital Filter for Sigma Delta Modulators）是一个独立的数字滤波器外设。

**配置：** DMNGT=10

**数据格式：** ADC 将 ADC_DR 的 **低 16 位** 传给 DFSDM：
- bit15 = 符号位
- bit14:0 = 数据
- 超过 16 位有符号范围的部分被截断

DFSDM 读取数据后自动清除 EOC 标志。

### 29.4.29 自动延迟转换模式（AUTDLY）

AUTDLY=1 时，ADC 会等待软件读完上一笔数据后才启动下一次转换，自动匹配读取速度，防止低频时钟下溢出。

#### 基本规则

| 组 | 等待条件 |
|----|---------|
| 常规转换（每次 EOC 后） | ADC_DR 被读取 或 EOC 被清除 |
| 注入序列（每次序列结束后） | JEOS 被清除 |

- 注入序列内部的各转换之间**不插入延迟**，仅在序列结束时插入
- 不同组之间**不互相阻塞**（常规延迟期间注入可以立即开始）
- 延迟期间**硬件触发被忽略**，但软件触发仍有效

#### 常规 + 注入交互时序

| 场景 | 行为 |
|------|------|
| 常规延迟期间来了注入触发 | 注入**立即开始**，不受延迟影响 |
| 注入完成后常规延迟还没结束 | 常规继续等待延迟结束 |
| 注入期间来了常规触发 | 若发生在常规延迟窗口内 → **忽略**；若常规延迟已结束 → **挂起**，等注入结束后执行 |
| 注入序列结束后有延迟 | 延迟期间注入触发**被忽略** |

#### JAUTO=1 模式下的 AUTDLY

- 常规序列完成后立即开始注入序列（无延迟）
- 注入序列完成后插入延迟，等待 JEOS 清除
- JEOS 清除后才允许开始下一轮常规序列

**停止流程（JAUTO=1 + CONT=1 + AUTDLY=1）：**
1. 等待 JEOS=1（确保不再自动重启）
2. 清除 JEOS
3. 设 ADSTP=1
4. 读取常规数据

若不按此流程，JEOS 在 ADSTP 之后被清除可能导致常规序列异常重启。

### 29.4.30 模拟看门狗（AWD1/2/3）

三个模拟看门狗，监控转换结果是否在设定的阈值窗口内。超范围时置位 AWDy 标志，可产生中断（AWDyIE）。

#### 阈值设置

通过 ADC_HTRy（高阈值）和 ADC_LTRy（低阈值）寄存器配置，最大 **26 位**（配合过采样）。

**低分辨率时的对齐要求：**

| 分辨率 | 阈值低位必须为 0 |
|-------|----------------|
| 16位 | 无 |
| 14位 | HTR[1:0]=0, LTR[1:0]=0 |
| 12位 | HTR[3:0]=0, LTR[3:0]=0 |
| 10位 | HTR[5:0]=0, LTR[5:0]=0 |
| 8位 | HTR[7:0]=0, LTR[7:0]=0 |

**比较在偏移计算之前进行**，使用原始转换值。

#### AWD1 — 通道选择

| AWD1SGL | AWD1EN | JAWD1EN | 监控范围 |
|---------|--------|---------|---------|
| x | 0 | 0 | 禁用 |
| 0 | 0 | 1 | 所有注入通道 |
| 0 | 1 | 0 | 所有常规通道 |
| 0 | 1 | 1 | 所有常规和注入通道 |
| 1 | 0 | 1 | 单个注入通道（AWD1CH） |
| 1 | 1 | 0 | 单个常规通道（AWD1CH） |
| 1 | 1 | 1 | 单个常规或注入通道（AWD1CH） |

#### AWD2/AWD3 — 通道选择

通过 **AWDCHy[19:0]** 位掩码选择多个监控通道，置任一 bit 即使能该通道的看门狗。

#### AWDx_FLAG 与 ADCx_AWDy_OUT

**AWDx_FLAG（软件管理）：**
- 超范围时硬件**置位**
- 必须软件写 1 清除
- 软件不清除就一直保持置位，即使后续转换回到范围内也不自动复位
- 软件清除后复位，直到下次超范围硬件再置位

**ADCx_AWDy_OUT（硬件自动管理）：**
- 超范围时硬件**置位**
- 下一次监控转换**在范围内**时硬件自动**复位**
- 连续超范围则持续保持 1
- **完全不受 AWDx_FLAG 状态影响**（FLAG 未清除时 OUT 仍正常跳变）
- 禁用 ADC（ADDIS=1）时复位
- ADSTP/JADSTP 无影响

该信号直接连接片内定时器的 ETR 输入，可用于实现硬件制动等快速响应。

### 29.4.31 过采样器（概述）

过采样单元对多次转换结果求和平均，由硬件完成，减轻 CPU 负担。

```
Result = (1/M) × Σ Conversion(tn)
```

- 最大 26 位输出（16 位 × 1024 倍过采样）
- 功能：求平均、降低数据率、提升 SNR、基础滤波

#### 配置参数

| 参数 | 寄存器位 | 说明 |
|------|---------|------|
| OSVR[9:0] | ADC_CFGR2 | 过采样率 N（2x ~ 1024x），即累加次数 |
| OVSS[3:0] | ADC_CFGR2 | 右移位数 M（0 ~ 10），即除法系数 2^M |

```
累加结果（最大 26 位）→ 右移 + 四舍五入 → ADC_DR
```

#### 转换时序

过采样模式下，每次采样都正常进行（采样时间不变），但 EOC 标志每 **N 次转换**才置位一次（最终结果就绪时）。

| 事件 | 时机 |
|------|------|
| EOSMP | 每次采样结束都置位 |
| EOC | 每 N 次采样结束后置位（最终结果可用） |
| EOS | N × 序列长度次采样结束后置位 |

等效延迟：**N × TCONV = N × (tSMPL + tSAR)**

#### 两种过采样触发方式

| 模式 | TROVS | 行为 |
|------|-------|------|
| 普通 | 0 | 一次触发连续完成 N 次转换，然后产生 EOC |
| 触发 | 1 | 每次触发只转换 1 次，N 次触发出一个结果。TROVS=1 时 DISCEN 被忽略（视为 1） |

触发模式适用于**定点去噪**（如滤除工频干扰），可以精确控制采样时刻。

#### 被注入打断时的行为

由 **ROVSM** 位控制：

| ROVSM | 模式 | 行为 |
|-------|------|------|
| 0 | **继续模式**（断点续采） | 累加器保留当前值，注入结束后**从断点继续**累加 |
| 1 | **重启模式** | 累加器**清零重新开始**，保证所有数据连续采集 |

- 继续模式要求两次注入触发之间至少能完成一次常规转换
- 重启模式下，注入触发周期必须 > 过采样周期，否则过采样永远无法完成

#### 过采样模式组合

| ROVSE | JOVSE | ROVSM | TROVS | 说明 |
|-------|-------|-------|-------|------|
| 1 | 0 | 0 | 0 | 常规 continued 模式 |
| 1 | 0 | 0 | 1 | **不支持** |
| 1 | 0 | 1 | 0 | 常规 resumed 模式 |
| 1 | 0 | 1 | 1 | 触发常规 resumed 模式 |
| 1 | 1 | 0 | X | **不支持** |
| 1 | 1 | 1 | 0 | 常规+注入 resumed 模式（因为只有一个累加器，常规必须重启） |
| 1 | 1 | 1 | 1 | **不支持** |
| 0 | 1 | X | X | 仅注入过采样 |

#### 过采样模式下的功能限制

| 功能 | 是否支持 |
|------|---------|
| 单次/连续转换 | 支持 |
| 软件/硬件触发 | 支持 |
| ADSTP 中止 | 支持 |
| CPU/DMA 读取 + 溢出检测 | 支持 |
| AUTDLY | 支持 |
| 可编程分辨率（RES） | 支持（低分辨率值同样累加、截断、移位） |
| 数据对齐（OVSS/LSHIFT） | **不支持**，过采样数据始终**右对齐** |
| 偏移校正（Offset） | **不支持**，ROVSE/JOVSE 使能时 OFFSETy_EN 被忽略 |
| 模拟看门狗 | 支持，但基于移位前的 **26 位值**比较，忽略 RES 位 |

#### 自动注入 + 过采样（JAUTO=1）

- 必须 ROVSE=1 + JOVSE=1（常规和注入同时过采样）
- ROVSM 被忽略
- 所有结果存入寄存器，可节省 DMA 资源
- 也可配合 TROVS=1 使用触发模式（JAUTO=1, DISCEN=0, JDISCEN=0, ROVSE=1, JOVSE=1, TROVS=1）

#### 双 ADC + 过采样

双 ADC 模式下，注入同步模式和常规同步模式支持过采样，两个 ADC 必须配置相同参数。其他双 ADC 模式不支持。

### 29.4.32 双 ADC 模式

ADC1（主 Master）和 ADC2（从 Slave）可工作在双 ADC 模式，由 **DUAL[4:0]**（ADC_CCR）选择。

#### 共享配置

- CONT、AUTDLY、DISCEN、DISCNUM[2:0]、JDISCEN、JQM、JAUTO 在主从之间共享
- 触发配置（EXTEN、EXTSEL、JEXTEN、JEXTSEL）只需配置主 ADC，从 ADC 的相应位被忽略
- 常规同步或交错模式下，设主 ADC 的 ADSTART/ADSTP 时从 ADC 自动跟随，但清除时刻不一定同步
- 注入同步或交替触发模式下，设主 ADC 的 JADSTART/JADSTP 时从 ADC 自动跟随
- 双 ADC 模式下可通过 **ADC_CDR**（公共数据寄存器）一次读取主从数据，通过 **ADC_CSR** 读取状态

#### 1. 注入同步模式（DUAL[4:0] = 00101）

主从 ADC **同时**转换各自的注入序列。

| 要求 | 说明 |
|------|------|
| 触发源 | 来自主 ADC 的注入触发复用器（JEXTSEL） |
| 序列长度 | 主从必须**相同** |
| 每笔采样时间 | 第 N 笔主从必须**相同** |
| 相同通道约束 | 两路 ADC 不可在不同位置采样同一个通道（采样时间不能重叠） |

**常规转换：** 常规转换各自独立进行，注入事件打断常规，注入结束后恢复。

**中断与数据读取：**
- 主从各产生各自的 JEOS 中断
- 若主从注入序列时长相等，可只使能一个 JEOS 中断，然后同时读取两组数据

**与 AUTDLY 结合：**
- 注入序列结束后，主从的 JEOS 都必须清除才接受新注入触发
- 常规转换方面，主从各自的 DR 被读后才接受新常规触发

**与 JDISCEN 结合：** 每次注入触发只转换一个通道（交替触发模式中的每一步）。

#### 2. 常规同步模式（DUAL[4:0] = 00110）

主从 ADC **同时**转换各自的常规序列。

| 要求 | 说明 |
|------|------|
| 触发源 | 来自主 ADC 的常规触发复用器（EXTSEL） |
| 序列长度 | 主从必须**相同** |
| 每笔采样时间 | 第 N 笔主从必须**相同** |
| 相同通道约束 | 两路 ADC 不可在不同位置采样同一个通道 |
| 注入支持 | 支持独立注入，注入会中止当前同步转换，结束后恢复 |

**数据读取方式：**

| 方式 | 配置 | 说明 |
|------|------|------|
| 双 DMA 通道 | DAMDF=00 | 主从各用一个 DMA 通道，各自读自己的 ADC_DR |
| 单 DMA 通道 | DAMDF=10 或 11 | 主从 EOC 都完成后产生一次 DMA 请求，读 **ADC_CDR**（主数据在低 16 位，从数据在高 16 位） |

**与 AUTDLY 结合：**
- 每次同步转换后，必须读 ADC_CDR（或主 ADC_DR）才能启动下一笔
- 序列结束后，必须读 ADC_CDR 才接受新触发
- 此组合限制只能使用常规通道，**禁止编程注入通道**
- 必须使能多 DMA 模式（DAMDF=10 或 11）
- 从 ADC 的转换时间必须**小于**主 ADC 的转换时间

#### 3. 交错模式（DUAL[4:0] = 00111）

主从 ADC **交替采样同一个通道**，提高等效采样率。通常用于常规组（一般一个通道）。

**触发源：** 来自主 ADC 的常规触发复用器。

**采样时序：**
1. 触发到来 → 主 ADC **立即开始**采样
2. 主 ADC 采样完成后，从 ADC **延迟 DELAY 个时钟**后开始采样
3. 确保同一时刻只有一个 ADC 在采样

**DELAY 配置（ADC_CCR）：**
- 最小值 = 1（确保主从模拟开关不会同时打开）
- 最大值 = 对应分辨率所需的周期数

**连续模式：** 主从都设置 CONT=1 时连续采样。

**数据读取：**
- 推荐使用 CDR（DAMDF=10 或 11），主从 EOC 都完成后才产生 DMA 请求
- 不支持独立的 DMA 请求

**注入支持：** 注入可打断交错转换，中止后**总是从主 ADC 恢复**（不一定是之前轮到谁）。

#### 4. 交替触发模式（DUAL[4:0] = 01001）

主从 ADC **轮流**被触发转换各自的**注入序列**（只支持硬件触发）。

**JDISCEN=0（非间断）：**
| 触发次序 | 行为 |
|---------|------|
| 第 1 次触发 | 主 ADC 转换全部注入通道 |
| 第 2 次触发 | 从 ADC 转换全部注入通道 |
| 第 3 次触发 | 主 ADC... |
| ... | 交替进行 |

**JDISCEN=1（间断）：**
| 触发次序 | 行为 |
|---------|------|
| 第 1 次触发 | 主 ADC 第 1 个注入通道 |
| 第 2 次触发 | 从 ADC 第 1 个注入通道 |
| ... | 逐通道交替，直到全部完成 |
| 完成后 | 重新从主 ADC 第 1 通道开始 |

**常规转换：** 常规转换独立于交替触发，注入会打断常规，结束后恢复。

**触发间隔要求：** 两次触发间隔 ≥ 1 个 ADC 时钟周期。

#### 组合模式

| DUAL | 组合 | 说明 |
|------|------|------|
| 00001 | 常规同步 + 注入同步 | 常规正在同步转换时，注入触发可打断并启动注入同步 |
| 00010 | 常规同步 + 交替触发 | 常规同步被交替注入触发打断，注入结束后主从常规**同步恢复** |
| 00011 | 注入同步 + 交错 | 交错转换被注入同步打断，恢复时**总是从主 ADC 开始** |

**组合模式共同要求：**
- 序列长度和每笔采样时间必须主从一致（或触发间隔足够长）

---

#### 双 ADC 模式的 DMA

双 ADC 模式下有两种 DMA 方式：

| DAMDF | DMA 方式 | 触发时机 | 数据位置 | 适用分辨率 |
|-------|---------|---------|---------|----------|
| 00 | 双 DMA 通道 | 各自 EOC | 各读各的 ADC_DR | 任意 |
| 10（32 位格式） | 单 DMA 通道 | 主或从任一 EOC，交替触发 | 读 **ADC_CDR2**，每次一个 32 位值 | > 16 位（过采样） |
| 10（16 位格式） | 单 DMA 通道 | 主和从 EOC 都到齐后触发 | 读 **ADC_CDR**，从[31:16] + 主[15:0] | 10~16 位 |
| 11 | 单 DMA 通道 | 4 个 8 位值就绪后触发 | 读 **ADC_CDR** | 8 位 |

**32 位格式 vs 16 位格式的区别：**

| | 32 位格式 | 16 位格式 |
|--|----------|----------|
| 寄存器 | ADC_CDR2 | ADC_CDR |
| 触发条件 | 一个 EOC 即触发（交替） | 两个 EOC 都到齐才触发 |
| 每次数据 | 单个 ADC 完整 32 位值 | 主 16 位 + 从 16 位打包 |
| 请求频率 | 较高（每次转换一次请求） | 较低（两次转换一次请求） |
| 过采样 | 支持（不截断） | 截断到低 16 位 |

**DAMDF=11（8 位格式）示例（交错模式）：**
```
第 1 次 DMA 请求: [从t0, 主t0, 从t1, 主t1] 一次搬 4 个 8 位
第 2 次 DMA 请求: [从t2, 主t2, 从t3, 主t3]
```

#### 双 ADC 溢出检测

任一路 ADC 发生溢出时，DMA 请求停止发送，保证已传输到 RAM 的数据全部有效。

#### 双 ADC 停止转换

设主 ADC 的 **ADSTP/JADSTP** 即可停止双 ADC 的转换，**从 ADC 的 ADSTP 无效**。停止完成后主从的 ADSTART/JADSTART 都由硬件清 0。

#### 双 ADC 的 DFSDM 模式

| 双 ADC 模式 | DFSDM 支持 |
|------------|-----------|
| 交错模式 | DMNGT=10 使能，主从交替传输低 16 位到 DFSDM 单通道 |
| 同步模式 | 直接用单 ADC 模式 + 相同触发源即可，不需要双 ADC 模式 |

### 29.4.33 温度传感器

温度传感器测量器件的结温（TJ），范围 **-40~125°C**。

- 连接位置：**ADC2 VINP[12]**（VSENSE）
- 使能控制位：**TSEN**（ADC_CCR）
- 采样时间要求：必须大于产品数据手册规定的稳定时间
- 不使用时可通过关闭 TSEN 位进入掉电模式省电

#### 使用步骤

1. 选择 ADC 输入通道并配置采样时间（查数据手册）
2. 设 TSEN=1 唤醒传感器
3. 启动 ADC 转换
4. 读取 VSENSE 数据
5. 使用公式计算温度：

```
温度 = (TS_CAL2 - TS_CAL1) / (TS_CAL2_TEMP - TS_CAL1_TEMP) × (TS_DATA - TS_CAL1) + TS_CAL1_TEMP
```

| 参数 | 说明 |
|------|------|
| TS_CAL1 / TS_CAL2 | 出厂校准值（存在芯片中） |
| TS_CAL1_TEMP / TS_CAL2_TEMP | 校准时的温度点（查数据手册） |
| TS_DATA | ADC 实际转换的 VSENSE 值 |

**注意：** 传感器从掉电唤醒到输出稳定需要启动时间。建议 **ADEN 和 TSEN 同时设置**，节省时间。

### 29.4.34 VBAT 电源监测

- 连接位置：**ADC2 VINP[14]**
- 使能控制位：**VBATEN**（ADC_CCR）

VBAT 电压可能比 VDDA 高，因此内部通过 **4 分频**后再送 ADC。转换结果必须 **×4** 才是真实 VBAT 电压。

只在需要时才使能分频器，避免不必要的电池消耗。

### 29.4.35 内部参考电压监测（VREFINT）

- 连接位置：**ADC2 VINP[13] / VINP[15]**
- 使能控制位：**VREFEN**（ADC_CCR）

#### 利用 VREFINT 计算实际 VDDA

VREFINT 出厂时在 VDDA=3.3V 下标定，可用于反推实际 VDDA：

```
VREF+ = 3.3V × VREFINT_CAL / VREFINT_DATA
```

#### 将 ADC 转换值转为绝对电压

已知 VDDA 时：
```
VCHANNELx = (FULL_SCALE / VDDA) × ADC_DATA
```

VDDA 未知时（利用 VREFINT）：
```
VCHANNELx = (FULL_SCALE / (3.3V × VREFINT_CAL / VREFINT_DATA)) × ADC_DATA
```

| 参数 | 说明 |
|------|------|
| VREFINT_CAL | VREFINT 出厂校准值 |
| VREFINT_DATA | ADC 实际转换的 VREFINT 值 |
| FULL_SCALE | 最大数字量（16 位=65535，8 位=255） |

### 附：VSENSE 与 DTS 的区别

芯片内部有两种温度监测方式：

| | VSENSE（ADC 通道） | DTS（数字温度传感器） |
|--|-------------------|-------------------|
| 原理 | ADC 转换模拟电压 | 温度→频率→计数，直接输出数字值 |
| 依赖 | 需使能 ADC2 | **独立外设**，不依赖 ADC |
| 功耗 | 需开整个 ADC | 更低，可在低功耗模式下工作 |
| 唤醒 | 不支持 | 支持（LSE 模式异步唤醒） |
| 用途 | 顺带测温 | 专用温度监测、过热保护
