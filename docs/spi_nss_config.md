# STM32MP157 SPI 片选 (NSS/SS) 配置参考

> 来源：RM0436 Rev 7, Section 54.4.7 Slave select (SS) pin management

## 基本概念

| 模式 | SS 角色 |
|------|---------|
| 从机 (Slave) | 标准片选输入，主机通过它选中从机 |
| 主机 (Master) | 输出：驱动从机片选 / 输入：多主机冲突检测 |

SS 有效电平由 `SSIOP` 位决定：外部 SS 引脚电平 == SSIOP 时视为有效电平。

---

## 管理方式总览

```
                 ┌─ SSM=1 ─── 软件管理：内部 NSS 由 CR1.SSI 位驱动
                 │            外部 SS 引脚释放，可用于 GPIO 或其他 AF
SS 管理 ────────┤
                │           ┌─ SSOE=1 ─── 硬件输出（仅主机）
                └─ SSM=0 ───┤            SS 由外设控制，绑定 CSTART/EOT
                            │            必须设置 TSIZE > 0
                            │
                            └─ SSOE=0 ─── 输出禁用
                                          主机：多主机模式，SS 被拉低 → MODF
                                          从机：标准片选输入
```

---

## 三种配置详解

### 1. SSM=1（软件管理）

- 内部 NSS 信号 = `CR1` 中的 `SSI` 位控制
- 外部 SS 引脚释放，可用于 GPIO 或其他 AF
- **限制**：无自动边沿同步保护。SSI 只能在总线空闲且 SCK 处于空闲电平时切换。

### 2. SSM=0, SSOE=1（硬件输出，仅主机）

- SS 引脚由 SPI 外设硬件驱动
- **功能绑定到 CSTART 和 EOT**
- 必须设置 **TSIZE > 0** 来控制 SS 输出
- **即使 SS 引脚不用作 SPI AF，SSOE=1 也应保持**，以确保内部 SS 输入逻辑默认电平，防止误触发 MODF

**SS 波形 3 种子情况：**

| SSOM | SP 协议 | SS 波形 |
|------|---------|---------|
| 0 | Motorola (000) | CSTART=1 → SS 有效，**一直保持**到 EOT 或挂起 |
| 0 | TI (001) | TI 模式自动产生脉冲 |
| 1 | Motorola (000) + MIDI>1 | 每帧之间 SS 脉冲无效电平，持续 **MIDI-1** 个 SCK |

### 3. SSM=0, SSOE=0（输出禁用）

**主机模式：**
- 用于多主机拓扑
- SS 被外部拉为有效电平 → **MODF（模式故障）**
- MODF 后果：硬件自动清 MASTER=0、SPE=0、TX/RX FIFO 清空

**从机模式：**
- SS 为标准片选输入
- 从机需要检测 SS **起始边沿**（无效→有效）才能同步
- **不能用于 SS 固定接低**的场景

---

## SSM/SSI 与 SS 输出是两套独立逻辑

SSM 和 SSI 只控制 **内部 NSS 输入**，不控制 SS 引脚输出。手册原文：

> *"The value of this bit (SSI) is forced onto the peripheral SS input and the I/O value of the SS pin is ignored."*

强调的是 SSI 替代了外部引脚作为内部输入源，不意味 SSM=1 只限从机。

参考 Figure 617 框图，两套逻辑互不干扰：

| 方向 | 控制位 | 功能 |
|------|--------|------|
| 内部 NSS **输入** | SSM, SSI | MODF 检测（主机）/ 从机选通（从机） |
| SS 引脚**输出** | SSOE, SSOM, MIDI, MSSI | 驱动外部从机片选 |

**主机模式下用 SSM=1**：设 SSI 与 SSIOP 不同（如 SSIOP=0 设 SSI=1），内部 NSS 输入永远"非有效"，防止 MODF。代价是失去多主机冲突检测。SSOE=1 时仍能正常驱动外部 SS 输出。

**从机模式下用 SSM=1**：用 SSI 位软件控制从机选通，不需要外部 CS 引脚。

即使 SSM=1（内部 NSS 由软件决定），SSOE=1 照样能驱动外部 SS 引脚输出，两者各管各的路。

---

## MSSI 和 MIDI 时序

仅在 SSM=0, SSOE=1 时有效。

### Figure 618 — 数据流时序控制（SSOM=0, SSM=0）

```
SS   \___________________________/~~~~~~~\___________________________
      |<--- MSSI x tSCK ---->|            |
                             |<--------->|
SCK  ________________________|  DSIZE+1   |_____|   MIDI    |________
                             |<-- 帧 -->|      |<-------->|
MOSI X_______________________X   DATA    X______X   DATA   X_________
```

- **MSSI[3:0]**：SS 有效后延迟多少个 SCK 才开始发时钟 → 给从机建立时间。**MSSI 是最小延迟**：SCK 启动需同时满足"已过 ≥ MSSI 周期"和"TxFIFO 有数据"。数据在 MSSI 周期内到达则需等足；数据晚于 MSSI 则数据到后立刻起 SCK，不重新计时。
- **MIDI[3:0]**：两帧之间 SCK 空闲的 SCK 周期数

### Figure 619 — SS 帧间脉冲（SSOM=1, SSM=0）

四种 CPOL/CPHA 组合，均要求 MIDI > 1：

```
CPHA=0, CPOL=0:
SS   \___/~~~~~~~\___/~~~~~~~\___
      |<-MSSI->|          |<-- MIDI-1 -->|
SCK  _________|  帧数据   |_____________|  帧数据
              |<--------->|             |<--------->

CPHA=1, CPOL=0:   SS 下降沿对齐 SCK 第二边沿
CPHA=0, CPOL=1:   类似 I，极性反转
CPHA=1, CPOL=1:   类似 II，极性反转
```

关键：**SSOM=1 时，MIDI 必须 > 1 才会产生帧间脉冲。MIDI=0 时 SS 连续有效。**

---

## 各器件对 SS 的要求

| 器件类型 | SS 要求 | 适用配置 |
|----------|---------|----------|
| 74HC595 类移位寄存器 | 无所谓，不看 CS | 任意 |
| LED 数码管控制器 | SCK 帧间间隔即可区分数据帧 | SSOM=0, MIDI>0 |
| W25QXX SPI Flash | 整条命令期间 CS 必须连续低 | SSOM=0 |
| 标准 SPI 从机设备 | CS 完整包住数据帧 | SSOM=0 |

**Flash 需要 SSOM=0**：Flash 以 CS 上升沿为命令边界。如果帧间 SS 脉冲变高，Flash 认为命令结束 → 后续字节被当成新命令 → 协议失败。

## 当前项目配置

```
SPI4 寄存器状态（由 SpiCfg 写入）:

CFG2 bit29 SSOE  = 1     // SS 输出使能
CFG2 bit26 SSM   = 0     // 硬件 SS 管理
CFG2 bit28 SSIOP = 0     // SS 低有效
CFG2 bit30 SSOM  = 0     // 帧间不插入无效脉冲，SS 从 CSTART 保持到 EOT
CFG2 bits[3:0]  MIDI  = 8   // 帧间 SCK 空闲 8 周期
CFG2 bits[7:4]  MSSI  = 10  // SS 有效到首 SCK 延迟 10 周期
```

**结论：当前 SpiCfg 已正确配置了 SSOE=1, SSOM=0, SSM=0，SS 波形对 Flash 兼容——整个传输期间 CS 保持有效，无帧间脉冲。**

---

## 运行时切换策略

当前 SpiCfg 配置（SSOE=1, SSM=0, SSOM=0）对 Flash 和 LED 均适用，无需切换。如果将来有器件需要帧间脉冲：

```c
// 需要帧间脉冲时
SPI4->CFG2 |= 1 << 30;       // SSOM = 1
// 恢复连续 SS
SPI4->CFG2 &= ~(1 << 30);    // SSOM = 0
```

# SPI 数据传输与使能/禁用流程

> 来源：RM0436 Rev 7, Section 54.4.10—54.4.12

---

## 54.4.10 — SPI 使能流程

### 从机侧

- 建议在主机发时钟前完成从机配置和使能
- **硬件 SS 管理 (SSM=0)**：从机忽略所有通信，直到检测到 SS 边沿（无效→有效），以此与主机同步。因此 SS 不能固定接低电平。
- **软件 SS 管理 (SSM=1)**：无此边沿检测保护。SSI 位只能在总线空闲且 SCK 处于空闲电平时切换。

### 主机侧

| 模式 | 通信开始条件 |
|------|-------------|
| 全双工 / 只发 | SPI 使能 + CSTART=1 + TxFIFO 非空（或下一次写 TXDR） |
| 只收 | SPI 使能 + CSTART=1，时钟立即开始运行 |

---

## 54.4.11 — 数据传输与接收（核心）

### 关键概念

| 概念 | 寄存器 | 含义 | 示例 |
|------|--------|------|------|
| **DSIZE** | CFG1[4:0] | 一个数据帧的位数 | 0x7 = 8-bit |
| **FTHLV** | CFG1[7:5] | FIFO 阈值，定义几帧组成一个数据包 | 0 = 1 帧/包；4 = 16 帧/包 |
| **TSIZE** | CR2[15:0] | 一次传输的总帧数 | 设为 0 则无限传输 |
| **TSER** | CR2[31:16] | 传输扩展：TSIZE 用完后自动从 TSER 重载 | 实现无间断持续流 |

**数据帧** vs **数据包** vs **数据访问**：
- **帧** = DSIZE 定义的 bits 数，是 SPI 总线上传输的最小单位
- **包** = FTHLV 定义的帧数，是 FIFO 就绪标志（RXP/TXP）的触发单位
- **访问** = CPU/DMA 对 TXDR/RXDR 的读写方式（8/16/32-bit），可以用一次 32-bit 访问处理 4 个 8-bit 帧（packing）

> **注意点 1 — FTHLV 与 packing**：FTHLV ≠ 0 时用于 packing，将多个帧打包一起写入 FIFO。FTHLV 的上限 = 32 / DSIZE（因为 FIFO 访问最大 32-bit）。例如 DSIZE=8 时最多 4 帧/包，DSIZE=16 时最多 2 帧/包。FTHLV=0 时每帧一包，不 packing。

### FIFO 架构

- TxFIFO 和 RxFIFO 独立，底层按字节组织（N × 8-bit，N 取决于实例）
- RxFIFO 容量与 DSIZE 关系：
  - DSIZE ≤ 8：N 帧
  - 8 < DSIZE ≤ 16：N/2 帧
  - 16 < DSIZE ≤ 24：N/3 帧
  - DSIZE > 24：N/4 帧
- 读 RXDR → 返回 RxFIFO 中最旧未读数据
- 写 TXDR → 放入 TxFIFO 队尾

### 三个包就绪标志（FIFO 事件）

| 标志 | 位 | 触发条件 | 用途 |
|------|----|----------|------|
| **RXP** | SR bit0 | RxFIFO 中 ≥ 1 个完整数据包 | 通知软件/DMA 读取一个包 |
| **TXP** | SR bit1 | TxFIFO 有空位容纳 ≥ 1 个完整数据包 | 通知软件/DMA 写入一个包 |
| **DXP** | SR bit? | RXP **或** TXP 任一触发 | 全双工合并处理，减少中断/DMA 次数 |

### RXP 和 TXP 的清除条件

- **RXP 清零**：RxFIFO 中的数据少于一个完整包时自动清零（读 RXDR 之后）
- **TXP 清零**：TxFIFO 填满到没有足够空间容纳下一个完整包时清零

### 数据包处理流程

```
RXP 置位 → 软件/DMA 读取一个包（对应 FTHLV 帧数的 RXDR 读）
       → 再查 RXP，若仍为 1 → 继续读下一包
       → 直到 RXP=0

TXP 置位 → 软件/DMA 写入一个包（对应 FTHLV 帧数的 TXDR 写）
       → 再查 TXP，若仍为 1 → 继续写下一包
       → 直到 TXP=0
```

### 非对齐尾包处理（重要特性）

当 TSIZE 不能被 FTHLV 整除时，最后一包不完整。硬件自动处理：

- **接收端**：多余读取返回 0，只有完整数据帧才从 FIFO 弹出。应用程序可以用与前面**完全相同的代码路径**处理最后一包，无需特殊逻辑。
- **发送端**：多余写入被丢弃，只有完整数据帧才推入 FIFO。TXP 会在只剩最后几帧且 FIFO 有空间时置位。
- 剩余帧数可通过 **RXWNE** 和 **RXPLVL**（SR 寄存器）查询。

### DXP 标志及其注意事项

DXP 是全双工下 TXP 和 RXP 的合并事件。使用时要注意：TXP 事件通常早于 RXP 发生，用 DXP 统一处理会延迟 TXP 的响应。对策：在传输开始前预先填充几个数据包到 TxFIFO，传输结束后通过 EOT 处理剩余接收数据。

### 传输控制

- **CSTART=1** → 传输开始。挂起后必须**先禁用 SPI 再重新使能**才能开始新传输。
- **CSUSP=1** → 挂起传输（清零 CSTART），当前帧完成后停止。
- **TSIZE=0 + CSTART=1** → 无限传输。此时**必须 FTHLV=0**（每帧一包），否则行为不可控。
- **TSIZE > 0** → 到达指定帧数后自动结束，EOT 置位。
- **TSER 非零** → TSIZE 用完后自动从 TSER 重载到 TSIZE，TSER 自行清零，TSERF 标志置位可触发中断。软件可在 TSERF 后写入下一个 TSER 值，实现**无限数据流**。

> **注意点 3 — TSIZE 16 位足够大**：TSIZE 最大 65535 帧，单次传输可达 64KB。大多数场景不需要 TSER 扩展，实际非对齐发生的概率很小，TSER 主要用于流式无限传输。

### 无限传输的两种方式

| | 方式一：TSIZE=0 | 方式二：TSIZE>0 + TSER 持续非零 |
|------|------|------|
| **启动** | 设 TSIZE=0，CSTART=1 | 设 TSIZE=N，TSER=M |
| **维持** | 无需干预，永久传输 | 在 TSERF 中断里写 TSER 下一个值 |
| **停止** | 只能 **CSUSP=1** 挂起 | 写 **TSER=0**，当前 TSIZE 发完后自动结束 |
| **结束标志** | 无 EOT，挂起后 SUSP=1 | 有 EOT，干净结束 |
| **约束** | 必须 **FTHLV=0**（每帧一包） | 无此限制 |

方式一永不产生 EOT，只能暴力挂起。方式二可自然收尾，更干净。

### TSIZE/TSER 对齐注意事项

传输 23 字节，DSIZE=8，FTHLV=4（每包 4 帧），32-bit FIFO 访问：

```
✓ TSIZE=16 + TSER=7                 (16+7=23，正确)
✓ TSIZE=12 + TSER=8; 最后一轮 TSER=3  (12+8+3=23，正确)
✗ TSIZE=15 + TSER=8                 (15 不与 4 对齐)
✗ TSIZE=8 + TSER=7; 最后一轮 TSER=8  (中间不对齐)
```

> **注意点 2 — 非对齐的约束**：只有**最后一次**（TSER 的最后一轮）可以不对齐，硬件会自动处理多余读写。中间的每一轮 TSIZE/TSER 扩展都必须与 FTHLV 对齐，否则中间就会出现不完整包，硬件处理会出错。

### 主机只收模式

- 半双工（COMM=11, HDDIR=0）或单工只收（COMM=10）
- 主机使能 + CSTART=1 → SCK 连续运行，直到 CSUSP 或 TSIZE 完成或 **MASRX=1 时 RxFIFO 满自动停止**
- 必须**先挂起再禁用** SPI，否则直接写 SPE=0 会截断当前帧，RxFIFO 被清空

### 流控

- **MIDI[3:0]**：帧间 SCK 空闲周期数，给从机处理时间
- **MSSI[3:0]**：SS 有效后到首个 SCK 的延迟周期数，给从机建立时间
- **UDRDR**：从机 TxFIFO 空时，自动发送此寄存器的值（"下溢数据"），主机可据此实现软件流控（类似 XOFF）

## 54.4.12 — SPI 禁用流程

### 主机模式禁用步骤

```
1. 等待 EOT（或 CSUSP=1 打断接收流）
2. 如果用了 CSUSP，等待 SUSP=1（确认最后一帧处理完成）
3. 读完所有 RxFIFO 数据（直到 RXWNE=0 且 RXPLVL=00）
4. 清 SPE=0 禁用 SPI
```

### 各类模式对应方法

| 模式 | 等待条件 | 说明 |
|------|----------|------|
| 全双工/只发 | TXC=1 且/或 EOT=1 | TSIZE>0 时两者等价 |
| 只收 | CSUSP=1 → SUSP=1 | 必须先挂起再禁用 |

> **注意点 4 — CSUSP 挂起 vs SPE=0 禁用**：CSUSP 是"优雅暂停"，**当前帧传输完成后**才停止通信，帧数据完整；SPE=0 是"暴力关断"，**当前帧立即被截断**，FIFO 清空。主机只收模式下必须先挂起再禁用，直接写 SPE=0 会导致时钟立即停止，当前帧被截断。

### 关键警告

- 直接清 SPE=0（不先等 EOT 或挂起）→ **当前帧被截断，RxFIFO/TxFIFO 全部清空，未读数据丢失**
- 禁用 SPI 后 FIFO 清空，所以步骤 3 必须在步骤 4 之前完成
- 从机模式：禁用 SPI 时所有进行中的数据丢失

### 当前 `SpiTxRx` 对照

```
      手册要求                       SpiTxRx 实现
────────────────────────────────────────────────────
1. 等 EOT                     →   while ((SR & (1<<3)) == 0)  ✓
2. 挂起确认（不适用 EOT 路径）  →   跳过                         ✓
3. 读完 RX (RXWNE=0, RXPLVL=00)→   未显式检查                   △
4. SPE=0                      →   CR1 &= ~1                   ✓
```

第 3 步未做显式检查，但因为 while 循环里 RX 计数到达 len 后才退出，且 EOT 后不会再收到新数据，实际 FIFO 已空。
